# ピッチ台本を作る

## 基本の流れ
痛み → 解決 → デモ → 仕組み → 人が介在するところ → 締め。冒頭に、**会場への問いかけ（掴み）**を入れ、締めで、その問いに戻る。

## 作り方
1. **誰が話すか**を、先に聞く。話し手に子どもがいない・経験がない場合は、「うちの子」など、**事実でない一人称を、台本に書かない**。経験は、当事者に、インタビュー形式で語ってもらう（短く・自分の言葉で・1回15秒以内）。
2. 当事者の言葉は、**本人が実際に言った言葉**を使う。作り話を足さない。埋まらない部分は、〔 〕で空欄にして、「未決定」に並べる。
3. 時間は、日本語で、1分に約300字。**削る順番**を、先に決めておく（締めと原体験は、削らない）。
4. 名前の表記を、統一する（このリポジトリは、**ひらがな**の「いいまちがいとしょかん」）。ロゴの遊び（わざと言い間違え）は、聞かれたら答える。
5. デモには、**保険**を2段つくる（公開 URL → 記事の GIF → スクリーンショット）。音が核心なら、会場の音量を、直前に確認する。
6. **想定質問**の表をつける: プライバシー、音声の必然性、精度、複数人、テーマとの関係、今後、工夫。

## 事実の扱い（`claim-check` と併用）
- 実測できたことと、できていないことを、分けて話す（例: 本物の子どもの声は4本だけ）。
- 保存先・送信先は、実装どおりに言う。「外部に出さない」と言わない。「保存は、端末のブラウザ。ただし、文字起こしのために、音声は AquaVoice に、判定のために、文字は AI に送られる」。
- 「共有できる？」と聞かれる設計上の制約は、**今後の課題**として、先に用意しておく。

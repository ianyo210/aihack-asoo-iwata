# 説明を、実装と突き合わせる

## 手順
1. 説明の文章を、**主張ごとに分ける**（誰が・何を・どこへ送る／保存する、など）。
2. 各主張を、**実装を読んで**確認する（想像で答えない）。
   - 送信先: `api/` と `lib/` の `fetch` 先、環境変数。
   - 保存先: `lib/store.js`（`localStorage` / IndexedDB / サーバー）。
   - 端末をまたぐか: データが、どこに、誰から見えるか。
   - モデル・パラメータ: `api/transcribe.js`、`api/detect.js`。
3. 結果を、「合っている」「直したい」「確認できていない」の3つに分けて返す。**直す点は、言い換えの案**までつける。

## このリポジトリで、実際にあった食い違い
- 「AquaVoice から Gemini に送る」→ 実際は、**アプリ（サーバー）が**、AquaVoice の返した文字を、Gemini に送る。Gemini が受け取るのは、**文字だけ**。
- 「保存は、ブラウザの中だけ（消えない？）」→ ブラウザを閉じても消えない。ただし、**端末・ブラウザをまたげない**（子どもの端末の記録は、別の端末から見えない）。サイトデータの削除・シークレットでは消える。
- 「音声は外に出ない」→ 誤り。文字起こしのために、AquaVoice に送られる。
- 「ヒントなしでも、聞こえたまま書く」→ 誤り。素の文字起こしでも、**直される**（さんとさん → ほんとさ）。ヒントで、改善する（4本中3本）。「とうもころし」は、直された。
- 画面・GIF が、「実機のマイクの録画」か、「例データを入れた実画面」か。**実際と違う言い方をしない。**

## 未確認として扱うもの（断定しない）
- 2人以上の本物の子どもの声での、話者分離。
- 他社の文字起こしとの比較。
- 公式サイトの、根拠が確認できていない記載。

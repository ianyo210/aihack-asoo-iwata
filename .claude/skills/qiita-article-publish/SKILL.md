# 提出記事を、書いて・公開する

## 構成（HACKATHON.md の7項目）
作品名／困りごと／できること／使い方／AquaVoice・AIの活用／工夫／今後。
- **`AquaVoice` と `AI HACK` を、必ず本文に入れる。** タグは `AquaVoice` `AIHACK`。
- 記事は、**提出と、最終ピッチの両方**で使われる。ピッチで映すので、画面が大きすぎる画像は避ける。
- 「AquaVoice を使うメリット」を、独立した節で強調する（実際に効いたことだけ。他社比較はしていないなら、そう書く）。

## 正直さのルール（減点より、信頼）
- **実測したこと**と、**未確認のこと**を、分けて書く（例: 子どもの本物の声は4本だけ、複数人の話者分離は未確認）。
- 画像・GIF が、実機のマイクで録ったものでない場合は、**そう明記**する。AI で生成した画像は、その旨を明記する。
- 保存・送信先の説明は、実装と突き合わせる（`claim-check` を使う）。「外部に出さない」と言わない。
- 家族のコメントを載せるときは、**掲載の同意**を取り、名前は出さない。

## 公開用コピーの作り方
1. 下書き（`article.md`）から、HTML コメントを除く。
2. 空欄（【…】）が残っていないか、grep で 0 件を確認する。
3. 画像は、相対パスではなく、**GitHub の公開 URL**（`raw.githubusercontent.com/<owner>/<repo>/main/...`）で指す。リポジトリが公開なら、Qiita にアップロードしなくても表示される。URL が 200 を返すか、curl で確認する。
4. 公開用コピー（`docs/article/article-publish.md`）を作り、Qiita の編集画面に貼る。
5. Mermaid は、Qiita で描画される（コードブロックの言語名に `mermaid`）。

## 公開後
- `curl -L` で、ページが 200 か、タイトル・必須キーワード・画像・URL が入っているか確認する。
- **課題提出フォームに、記事の URL を送る。** 公開だけでは、提出にならない。締切は、スライドより延びることがある（運営の発言を確認）。
- 2回提出した場合は、新しい方のリンクで採点される。
